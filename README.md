# موقف الفواتير

موقع يحلل موقف كل فاتورة من حيث الائتمان والضمان والمتأخرات، ويفحص أي فاتورة جديدة قبل إصدارها، ويسجل طلبات الفواتير واعتماداتها. يعمل من GitHub Pages مع Google Sheet، بدون سيرفر أو قاعدة بيانات. شيتا العملاء والحركات للقراءة فقط، والكتابة تكون في شيت الطلبات عبر Apps Script.

## مصدر البيانات
- الملف لازم يكون محفوظًا كـ Google Sheet وليس xlsx، ومشاركًا بصلاحية «أي شخص لديه الرابط — عارض».
- الصق رابطه في شاشة **الإعدادات** مرة واحدة على كل جهاز. الرابط يُحفظ في المتصفح فقط ولا يدخل المستودع.

## الشيتات المطلوبة
| الشيت | الأعمدة المطلوبة | أعمدة اختيارية |
|---|---|---|
| `قاعده عملاء الشركه` | Account, Name, Credit limit | Eligible credit limit (الضمان), Payment schedule, Balance, Customer group, Worker Name, Warehouse Group |
| `حركات العملاء` | Account, Transaction type, Date, Amount | voucher, Invoice, Description |

هذه نفس أعمدة موقع حسابات العملاء. أسماء الشيتات تتغير من الإعدادات.

## طريقة الحساب
- **السداد:** كل تحصيل أو مرتجع يسدد أقدم مديونية مفتوحة للعميل (FIFO)، فتظهر لكل فاتورة قيمة مسددة ومتبقية.
- **الاستحقاق:** تاريخ الفاتورة + أيام `Payment schedule`.
- **تاريخ التحليل:** آخر حركة في الشيت وليس تاريخ اليوم، حتى لا يظهر تأخير وهمي إذا لم يُحدَّث الشيت.

### موقف الفاتورة الصادرة
| الفحص | النتيجة |
|---|---|
| الائتمان | تجاوز رصيد العميل بعد الفاتورة حده: **تحتاج متابعة**. ويقارن بالحد الحالي لأن الشيت لا يحفظ تاريخ الحدود |
| الضمان | يغطي الضمان أقدم الفواتير أولًا. غير مغطاة: **تحتاج متابعة**. متأخرة وغير مغطاة: **حرجة** |
| المتأخرات | متأخرة حتى 90 يومًا: **تحتاج متابعة**. أكثر من 90 يومًا: **حرجة** |

الموقف النهائي هو أسوأ نتيجة بين الفحوص الثلاثة.

### فحص فاتورة جديدة
| الفحص | النتيجة |
|---|---|
| الائتمان | تجاوز الحد، أو لا يوجد حد، أو العميل موقوف: **موقوفة** (يمكن جعل تجاوز الحد «تحتاج موافقة» من الإعدادات) |
| الضمان | الرصيد بعد الفاتورة أعلى من الضمان: **تحتاج موافقة**. المتأخرات أعلى من الضمان: **موقوفة** |
| المتأخرات | حتى 90 يومًا: **تحتاج موافقة**. أكثر من 90 يومًا: **موقوفة** |

يتجاهل التحليل المتأخرات الأقل من 1,000. عدد الأيام والمبلغ يتغيران من الإعدادات.

## طلبات الفواتير والاعتمادات
1. من شيت الطلبات افتح Extensions ثم Apps Script، والصق محتوى `apps-script/Code.gs` في السكربت.
2. غيّر `REQUEST_KEY` و`APPROVE_KEY` إلى مفتاحين مختلفين. لا ترفع المفتاحين الحقيقيين إلى GitHub.
3. من Deploy ثم Manage deployments، عدّل النشر الحالي واختر New version، مع Execute as: Me وWho has access: Anyone. بهذه الطريقة يبقى الرابط كما هو.
4. في **الإعدادات** بالموقع اكتب مفتاحك واسمك.

ينشئ السكربت شيت `طلبات الفواتير` وأعمدته عند أول استخدام. والأعمدة تُقرأ باسمها، فيمكن إضافة أعمدة أخرى أو تغيير ترتيبها، لكن لا تغيّر أسماء أعمدة النظام.

| نتيجة الفحص | موقف الاعتماد عند التسجيل |
|---|---|
| سليمة | لا يحتاج اعتماد |
| تحتاج موافقة أو موقوفة | قيد الاعتماد، إلى أن يعتمده أو يرفضه صاحب مفتاح الاعتماد |

القرار يُسجل مرة واحدة ولا يمكن تغييره من الموقع، والرفض يحتاج سببًا.

## الخصوصية
الكود عام على GitHub Pages ويحتوي على رابط Apps Script فقط، ولا يقبل الرابط أي طلب بدون مفتاح. أما شيت العملاء فأي شخص يملك رابطه يستطيع قراءته، لأن Google لا تسمح بالقراءة من موقع ثابت بدون هذه المشاركة، فلا ترسل الرابط إلا لمن يحق له رؤية البيانات. شيت الطلبات لا يحتاج مشاركة عامة.

اسم مقدم الطلب والمعتمد يُكتب يدويًا في الإعدادات، فالسجل يثبت أن صاحب المفتاح نفّذ العملية، لكنه لا يثبت هوية الشخص. لا تعطِ مفتاح الاعتماد إلا للمعتمدين، وغيّره إذا خرج أحدهم من الصلاحية.

## الملفات
| الملف | المحتوى |
|---|---|
| `index.html` | هيكل الشاشات |
| `styles.css` | التنسيق |
| `engine.js` | الحسابات والقواعد |
| `app.js` | قراءة الشيت والواجهة |
| `demo.js` | بيانات نموذجية للتجربة |
| `apps-script/Code.gs` | سكربت شيت الطلبات والاعتمادات |
| `test/engine.test.js` | اختبارات الحسابات: `node test/engine.test.js` |
| `test/script.test.js` | اختبارات السكربت: `node test/script.test.js` |
| `tools/serve.js` | تشغيل محلي: `node tools/serve.js` ثم `http://localhost:8321` |

## النشر
فعّل GitHub Pages على فرع `main`. بعد ذلك يُنشر أي `git push` خلال دقيقة أو اثنتين. عند تعديل ملف، غيّر رقم `?v=` في `index.html` حتى تجلب المتصفحات النسخة الجديدة.
